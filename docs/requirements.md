# 图生视频创作平台 · 需求说明

| 项目 | 内容 |
|---|---|
| 版本 | v5.2（2026-11-22） |
| 定位 | 考生登录后按题目生成图生视频并下载；管理员管理考生、题目、配额、开放时段、模型与用量 |
| 规模 | 单批 100 人；题目 3~4 道（可扩展）；每题默认 2 次机会 |

---

## 0. 一页概要

| 维度 | 结论 |
|---|---|
| 系统做什么 | 考生登录 → 选题目 → 传图写提示词 → 生成 → 下载；管理员管账号、配额、时段、模型、用量 |
| 核心难点 | 稳定调用模型（并发与失败重试）、稳定下载（CDN 与断点续传）、配额与时段在服务端严格生效 |
| 配额规则 | 每题默认 2 次；总次数 = 各题次数之和；管理员可逐人逐题调整 |
| 时段规则 | 管理员配置开放时段；时段内可提交生成，时段外只读 |

---

## 1. 项目概述

### 1.1 定位

一套轻量的在线创作平台。考生用自己的账号登录，按管理员配置的题目上传图片、填写提示词，生成 15 秒视频并下载到本地；管理员在后台管理考生账号、题目、生成配额、开放时段、可用模型，并查看整体用量。

### 1.2 系统组成

| 模块 | 承担的事 |
|---|---|
| 用户与账号 | 账号生成、批量导入、密码管理、导出、启禁用 |
|  |                                                |
| 配额管理 | 每人每题的生成次数、扣减与退还、批量与单人调整 |
| 时段管理 | 开放时段配置、时段内外的权限差异、临时延长 |
| 创作与生成 | 图片上传、提示词、异步生成、排队与进度 |
| 作品与下载 | 作品列表、在线预览、单条与打包下载 |
| 模型管理 | 引擎启停、默认引擎、单价、并发上限 |
| 用量统计 | 按人/按题/按模型/按天统计与导出 |
| 操作日志 | 管理员关键操作留痕 |

### 1.3 设计原则（按优先级）

1. **生成要稳**：模型调用失败率控制在个位数，失败自动重试且不吞考生次数。
2. **下载要稳**：成片必须拿得走，下载走 CDN，支持断点续传。
3. **规则在服务端**：配额、时段、次数全部由服务端判定，前端只做展示。
4. **后台能自证**：用量、失败率随时可查，问题能定位到人、到题目、到模型。

## 3. 核心流程

### 3.1 考生

| 步骤 | 动作 | 系统行为 |
|---|---|---|
| 1 | 打开网址，输入账号密码 | 校验账号状态与开放时段，登录后进入工作台 |
| 2 | 查看题目列表 | 每题显示要求、参考图（如有）、剩余次数 |
| 3 | 选择题目，上传图片 | 前端压缩至长边 1920 后上传，服务端内容审核 |
| 4 | 填写提示词 | ≤300 字，提供 3 条示例 |
| 5 | 提交生成 | 校验时段与配额 → 扣减次数 → 返回任务号 → 显示排队位次 |
| 6 | 等待与预览 | 3 秒轮询；出片后可在线播放 |
| 7 | 下载 | 一键下载 MP4，文件名含账号与题号 |
| 8 | 继续下一题 | 直到各题次数用完或全部完成 |

### 3.2 管理员

| 步骤 | 动作 |
|---|---|
| 1 | 配置模型：启用哪些引擎、默认引擎、单价、并发上限 |
| 2 | 建题目：名称、要求、参考图、排序；题目数量按批次实际需要增减 |
| 3 | 导入考生：Excel 批量导入并自动生成账号密码，导出密码条 |
| 4 | 分配配额：按题批量设置默认次数，必要时逐人逐题调整 |
| 5 | 配置开放时段：设置可提交的时间窗，必要时临时延长 |
| 6 | 查看用量：生成数、成功率、各模型分布；结束后导出明细与成片 |

## 4. 功能需求

### 4.1 用户管理

| 项 | 要求 |
|---|---|
| 账号规则 | 学号/考号即账号，全局唯一；也支持系统按规则自动生成 |
| 密码生成 | 随机 8 位，含大写、小写、数字，剔除易混字符 O/0/I/l/1 |
| Excel 模板 | 提供标准模板下载，列：姓名、账号（可留空自动生成）、备注 |
| 批量导入 | 上传 Excel 一次导入；逐行校验，重复账号/空姓名等错误按行号回报；导入结果给出成功数、失败数与原因 |
| 单条管理 | 新增、编辑、删除单个考生；支持按账号/姓名搜索 |
| 密码查看与重置 | 管理员可查看初始密码（加密存储、仅在生成后指定时间内可查看），可单个/批量重置 |
| 导出 | 导出 Excel/CSV：账号、姓名、初始密码；另提供可打印的密码条页面 |
| 启禁用 | 禁用后无法登录，已提交任务不中断 |
| 批量操作 | 选中多人批量重置密码、批量禁用、批量调整配额 |
| 会话 | HttpOnly Cookie，24 小时有效；同账号后登录踢掉前一个会话 |
| 登录保护 | 连续 5 次失败锁定该账号 5 分钟；记录登录时间与 IP |

### 4.3 配额管理

| 项 | 要求 |
|---|---|
| 默认规则 | 每题默认 2 次；考生总次数 = 各启用题目的次数之和（3 题 6 次，4 题 8 次） |
| 扣减 | 提交生成即扣该题次数；服务端单条更新，保证并发下不超发 |
| 退还 | 生成失败、审核不通过不扣（或扣后立即退还），记录退还原因 |
| 按题批量设置 | 选定某道题，设置该题全体考生的次数（如统一改为 3 次） |
| 按人设置 | 选定某考生，逐题设置次数；也可一键把该考生所有题设为同一数值 |
| 多人批量 | 勾选多名考生，对指定题目批量加/减次数 |
| 下调保护 | 若新次数小于该生已用次数，需二次确认并说明，避免出现「已用 3 次而总额改为 2」的矛盾数据 |
| 调整留痕 | 每次调整记录：操作人、时间、对象、原值、新值、原因；考生端该题显示「已调整」标记 |
| 展示 | 考生端每题显示「剩余 N 次 / 共 M 次」；工作台顶部显示总剩余 |
| 用完提示 | 某题次数用尽后提交按钮置灰，提示「本题机会已用完」 |

### 4.4 开放时段管理

| 项 | 要求 |
|---|---|
| 时段字段 | 时段名称、开始时间、结束时间、启用状态、备注 |
| 多时段 | 可配置多个时段（如上午场、下午场）；任一时段内均可提交 |
| 生效判定 | 提交生成时校验「当前时间是否在某个启用时段内」，由服务端判定 |
| 时段内 | 正常创作与提交；页面顶部显示「本时段剩余 XX 分」 |
| 时段外 | 可登录、可查看历史作品与下载，提交按钮置灰并提示下一次开放时间 |
| 临时延长 | 管理员可延长当前时段结束时间，需二次确认并写操作日志 |
| 已提交任务 | 时段结束后，已提交的生成任务继续跑完并出片，不受时段影响 |
| 时段变更 | 变更后立即生效；考生页面在下一次轮询时刷新状态 |

### 4.5 创作

| 项 | 要求 |
|---|---|
| 图片 | JPG/PNG/WEBP，≤10MB；前端长边压到 1920；上传即审核 |
| 提示词 | ≤300 字；提供 3 条示例便于快速上手 |
| 草稿 | 图片与提示词本地暂存，刷新或断线重连后恢复 |
| 输出规格 | 15 秒、768P、MP4（H.264 + AAC），单文件 ≤30MB；参数按引擎配置生效 |

### 4.6 生成与排队

| 项 | 要求 |
|---|---|
| 提交 | 异步，1 秒内返回任务号，页面立即进入排队态 |
| 并发控制 | 服务端信号量限制在跑任务数，超出进队列 |
| 排队展示 | 「前面还有 N 人 / 预计等待 X 分 X 秒」，每 5 秒更新 |
| 超时 | 单条超过 600 秒判失败，释放并发位 |
| 重试 | 失败自动重试 1 次（指数退避）；仍失败退还次数并给出可读原因 |
| 出片 | 自动转存对象存储，前端拿自有域名链接 |

### 4.7 作品与下载

| 项 | 要求 |
|---|---|
| 作品列表 | 按题目分组，状态分为生成中 / 可下载 / 失败 |
| 在线预览 | 点击可播放，便于确认为目标版本 |
| 单条下载 | 文件名：账号_题号_第N次_时间戳.mp4 |
| 批量下载 | 本人全部作品打包 zip 一次下载 |
| 下载可靠性 | 支持 Range 断点续传；失败给出重试按钮并提示原因 |
| 产物持久 | 成片独立于任务记录存储，清理任务表不影响文件 |
| 链接安全 | 下载地址为短时效签名 URL（30 分钟），仅本人登录态可取 |

### 4.8 模型管理

| 项 | 要求 |
|---|---|
| 模型列表 | 展示引擎代号（对外名称）、内部标识、分辨率、时长、单价、并发上限、状态 |
| 启用/停用 | 停用后不再承接新任务；已在跑的任务不受影响 |
| 默认引擎 | 设一个默认；需要时可开启白名单允许管理员指定任务使用其他引擎 |
| 单价维护 | 每个引擎可维护「元/秒」，用于后台用量折算 |
| 并发上限 | 每个引擎可设最大同时任务数，作为服务端限流依据 |
| 健康状态 | 展示最近成功/失败数、平均耗时，异常时标红 |

### 4.9 用量统计

| 维度 | 指标 |
|---|---|
| 总览 | 考生数、生成条数、成功数、失败数、成功率、累计生成时长 |
| 按考生 | 每人生成次数、剩余次数、失败次数、最后活跃时间 |
| 按题目 | 每题生成条数、平均耗时、失败率 |
| 按模型 | 各引擎调用条数、时长、占比 |
| 按天 | 每日生成量与失败率趋势 |
| 导出 | 明细 CSV；成片按考生/按题打包下载 |

### 4.10 操作日志

记录管理员关键操作：导入考生、重置密码、调整配额、增减题目、修改时段、启停模型。字段：操作人、时间、对象、动作、变更前后值、备注。可按时间与操作人检索。

## 5. 非功能需求

### 5.1 稳定性：模型调用

| 保障项 | 措施 |
|---|---|
| 并发控制 | 服务端信号量 + 队列，不依赖「多开 Key」（限额按账号算） |
| 失败重试 | 指数退避 + 抖动，最多 1 次，不放大重试风暴 |
| 超时处理 | 单任务 600 秒硬超时，主动取消，释放并发位 |
| 熔断 | 连续失败超阈值自动降速提交，恢复后逐步放量 |
| 状态对账 | 定时扫描长时间「生成中」任务，主动查询终态，清理僵尸任务 |
| 降级开关 | 一键切到低分辨率引擎（480P），保出片优先于画质 |

### 5.2 稳定性：下载

| 保障项 | 措施 |
|---|---|
| CDN 直出 | 下载走 CDN 签名地址，源站只做鉴权 |
| 断点续传 | 支持 Range 请求 |
| 并发下载 | 100 人同时下载，单人 ≥2MB/s |
| 产物持久 | 对象存储独立分区；存储余量低于 20% 告警 |

### 5.3 平台并发配额（调研结论）

| 平台 | 默认并发 | 提交速率 | 提额方式 | 可争取上限 |
|---|---|---|---|---|
| MiniMax（H3 / H3-Highspeed） | 30 个进行中任务 | 300 次/分钟 | 邮件 api@minimax.io 或商务 | 未公开，按用量谈 |
| 火山方舟（Seedance 系列） | 企业 10，个人 3 | 企业 600 / 个人 180 次每分钟 | 控制台工单 | 最高 1000 |

> **本期选型已定**：只使用 MiniMax 一家（H3-Highspeed 768P 为主，H3-Lite 480P 作降级备用），不再接入 Seedance 系列。因此本节的平台对比仅作背景参考，实际执行以 MiniMax 的额度与提额结果为准。

- **MiniMax 官方限流表未区分个人/企业**，付费账号同为 300 RPM / 30 并发；火山方舟则明确区分（企业 10 / 个人 3）。
- 限额按账号（主体）计算，不随 API Key 数量增加。
- 任务从提交起即占用并发，直到进入终态；客户端断开不释放。
- 提额只能走商务或邮件（MiniMax）／工单（火山），无自助入口；建议签约前用低档位（480P、4 秒）并发提交 40 个任务实测真实并发值。

### 5.4 并发与排队要求

单批 100 人，4 道题时每人最多 8 次，极端情况一批最多 800 个任务。按单条约 2 分钟估算：

| 并发 | 600 个任务跑完 | 800 个任务跑完 |
|---|---|---|
| 10 | 约 2 小时 | 约 2 小时 40 分 |
| 30 | 约 40 分钟 | 约 53 分钟 |
| 50 | 约 24 分钟 | 约 32 分钟 |
| 100 | 约 12 分钟 | 约 16 分钟 |

要求：平台并发至少提到 50，理想 100；服务端排队与进度提示必须可用。

### 5.5 性能指标

| 指标 | 目标 |
|---|---|
| 登录 | ≤800 ms |
| 生成提交 | ≤1 秒 |
| 状态查询 | ≤300 ms |
| 下载首字节 | ≤1 秒（CDN 命中） |
| 后台统计页 | ≤2 秒（万级记录） |
| Excel 导入 1,000 行 | ≤10 秒 |

### 5.6 安全

- 密码 bcrypt 加盐哈希；日志不打印明文密码。
- 管理后台独立入口与会话，与考生端隔离。
- 下载地址短时效签名，仅登录态可用。
- 上传类型与大小校验，内容审核前置。
- 配额与时段判定全部在服务端，前端不可篡改。

## 6. 技术方案

### 6.1 架构

```
浏览器（考生端 / 管理端）
        │
    Nginx（限流、静态资源）
        │
  FastAPI（登录 / 配额 / 时段 / 任务 / 下载鉴权 / 后台）
     │            │              │
  MySQL        Redis+队列     对象存储+CDN
（账号/配额/任务）（排队/并发）  （成片）
                     │
              Worker → 模型适配层 → MiniMax
```

### 6.2 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | Vue 3 + Vite | 体积小、开发快、兼容好 |
| 后端 | Python 3.11 + FastAPI | 异步、模型调用生态成熟 |
| 队列 | Redis + Celery | 排队、并发、重试 |
| 数据库 | MySQL 8.0 | 账号、配额、时段、任务、用量 |
| 存储 | 对象存储 + CDN | 成片存放与分发 |
| 表格 | openpyxl | Excel 模板导出与批量导入解析 |
| 转码 | ffmpeg | 统一封装、剥音轨、统一时长 |
| 部署 | Docker Compose 单机 | 一条命令起全套 |

### 6.3 模型适配层

对外统一呈现自有引擎代号，供应商只在配置文件出现：

```yaml
wq-v1:      { provider: minimax, model: MiniMax-H3-Highspeed, resolution: 768P, duration: 15, max_concurrency: 25 }
wq-v1-lite: { provider: minimax, model: MiniMax-H3-Lite,       resolution: 480P, duration: 15, max_concurrency: 25 }
```

对外接口只暴露 `engine / image / prompt / duration / aspect` 五个参数，换模型改配置即可。

### 6.4 配额与时段模型（关键设计）

```
candidates ──< quotas >── questions
                 │
                 └─ quota_total（默认 2）/ quota_used / adjusted_flag

time_windows ── 多条，任一启用的时段内可提交
```

- 扣减走单条 `UPDATE ... WHERE quota_used < quota_total`，靠数据库保证不超发。
- 失败退还走 `quota_used - 1`，与扣减成对出现。
- 新增题目后触发批量任务，为全体考生补建配额行。
- 提交时的校验顺序：账号状态 → 时段 → 配额 → 幂等 → 入队；任一不通过即拒绝并给出明确原因。

## 9. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 平台并发不足 | 排队过久 | 提前提额到 50+；必要时降 480P |
| 新增题目未补配额 | 考生某题次数为 0 | 新增后自动批量补建，并有校验任务巡检 |
| 配额被恶意消耗 | 用量异常 | 服务端硬扣减 + 单账号频率限制 + 用量突增告警 |
| 时段配置错误 | 考生无法提交 | 保存时校验起止时间；列表醒目展示当前生效时段 |
| 下载带宽不足 | 下载失败 | CDN 直出 + 断点续传 |
| 成片格式不符下游要求 | 无法使用 | 按下游规格锁定输出参数并提前公布 |
| 模型侧长时间故障 | 考生无法出片 | 熔断 + 降级到备用引擎 + 页面公告 |
