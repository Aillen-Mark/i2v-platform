# 风险清单

| 风险 | 处理 |
| --- | --- |
| 数据库和对象不是原子备份 | 维护窗口、隔离数据库快照、对象 JSONL 清单和 seal 一起确认，状态不一致时拒绝正常恢复。 |
| 真实故障域未验证 | 正式目标要求 HTTPS 和人工提供故障域标识，当前没有真实远端凭据，标记 BLOCKED。 |
| 已成功历史作品没有摘要 | 两种模式均标记 LEGACY_UNVERIFIED，完整模式附本次计算值，不回写业务表。 |
| 多个 Work 共享对象 | 报告 REFERENCE_CONFLICT，不自动修改或删除。 |
| 生成 Key 规则无法从名称推断所有历史对象 | 未知和 Mock Key 只做 UNCLASSIFIED_OBJECT，候选对象不删除。 |
| 全量 SHA-256 占用带宽 | 默认快速模式，完整模式有批次、并发、速率和总时长预算。 |
| 备份目标部分失败 | 清单记录失败，批次不 COMPLETE，目标冲突停止。 |
| 恢复对象不能覆盖 | 条件创建和摘要复核防止静默覆盖。 |
| 005 快照仍需人工冻结 | 工具拒绝活动 Work，运维必须执行暂停和隔离恢复。 |
| 上游 failed/cancelled 人工绑定 | 已改为明确拒绝，只有 queued/running/succeeded 可普通绑定，MEDIA_FAILED 只接受 succeeded。 |
| 候选孤儿扫描在线执行 | MySQL 页和 S3 页没有跨系统快照。仅作候选报告。写操作始终与对账工具隔离。 |
| 备份对象分页未覆盖首帧/题图 | public 桶仍需要独立保护方案。恢复已有成片和恢复全部后台业务需要分别验收。 |
| 备份目标支持有条件 PUT 尚待真实服务检验 | 依赖服务执行 If-None-Match: *。隔离 HTTP 端点已验证 412；正式服务需验证条件头与存储策略再启用。 |
| 备份密封的信任边界 | SHA-256 检测损坏和不完整清单。可同时覆盖对象、清单和摘要的备份管理员超出校验模型，需由权限隔离、版本保留与独立审计控制。 |
