# 实施顺序

1. 先新增与现有 SQL 迁移方式兼容的尝试表，保存状态、错误类别和请求时间。明确失败、未知和已接单分开，人工核对只接受可查询的上游 ID。
2. 再增加 Work 执行表，原子领取和记录已收件，使用进程心跳续租。所有执行状态写入以及成功和退额都校验当前租约。保留 Redis 作为限流与非权威协调。
3. 恢复扫描依据数据库到期时间，重新交给同一生成消费者；检查对应 Outbox 是否已发。恢复已确认出片但尚未完成上传的任务时核对已保存的对象键和摘要。每代独立对象路径，避免过期执行者覆盖新成片。
4. 运行迁移、针对性测试、真实进程终止和原有业务回归。记录已验证边界，不连接生产数据或真实供应商账号。
