# 媒体验真规范

| 项目 | 验收条件 |
| --- | --- |
| HTTP 下载 | 最终响应为 200，身份编码，具备可验证的长度或传输帧边界。有长度时同时对比实际字节数。源文件最多 100,000,000 字节，按块写入和计算 SHA-256。连接预算 5 秒，读空闲 20 秒，运行过程中按单调时钟检查 240 秒下载预算及任务剩余预算。中途断流时重查已有上游任务并下载完整对象。 |
| 期望时长 | 取提交时写入的 Work.duration_sec，它来自引擎。仅旧记录没有该字段时沿用既有 Celery 交接时长。 |
| 实际时长 | 优先 FFprobe 视频流 duration，其次 duration_ts × time_base。仅在容器只有该视频流时允许用 format.duration 兜底，以免长音轨掩盖短视频。输入和输出均检查实际视频时长与目标相差最多 0.5 秒，音频与视频相差最多 0.5 秒。 |
| 容差依据 | 给帧周期、音频编码帧和容器舍入留余量。全程不循环、不补画面、不通过加长音轨修正短视频。15 秒任务的允许区间为 14.5–15.5 秒。 |
| 画幅和分辨率 | 保留素材画幅，奇数像素边最多补一像素。校验短边至少 16、长边最多 4096、画面像素不超过 4096×2160。已知 480P/768P 按包含横竖画幅的档位范围校验，短边分别为 384–540/614–864，长边不超过 1010/1614。2K 短边 1100–1536、长边不超过 3072。档位范围是本轮为 adaptive 输出采用的兼容假设，真实供应商出片仍需抽样。缺少历史档位的作品应用通用尺寸边界。 |
| 音轨 | 有音轨时转码首条音轨。无音轨时按实际视频时长生成静音 AAC。坏音轨产生明确错误。输出为 48 kHz、双声道 AAC，验真允许单声道和双声道以兼容旧检查点。 |
| 输出 | faststart MP4、H.264、偶数宽高、AAC、恰好两个流，大于 0 字节且不超过 30,000,000 字节。检查 FFprobe 容器识别和 MP4 brand。FFmpeg 用严格错误检测解码整段影音，每个新成片和接管复用的旧对象都执行。 |
| 时间上限 | FFprobe 单次 30 秒，转码 240 秒，完整解码 120 秒。各阶段同时受 600 秒执行片总预算约束。超时或存储暂时不可用时交原恢复流程。确定性媒体验真失败进入人工核对。 |

容差内保留整数业务时长字段用于原有展示和统计，探测到的小数时长、转码耗时和字节数单独记录。
