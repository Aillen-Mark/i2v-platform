# 008 成片对象完整性、对账和异地备份

**优先级** P0
**审查结论** 已确认，静态审查。单条下载 HEAD 与归属校验已实现。
**发布状态** 待批准

## 问题背景

MySQL 成片记录与 S3 对象分别提交。文件发布失败、对象后续丢失或两者之间崩溃需要可追踪。

## 实际代码依据

`upload_and_finish()` 调用 `put_object` 后写成功，未核对对象完整性。单条下载检查对象存在，作品列表根据数据库标记展示。批量下载经 FastAPI；CDN 通过替换已签名 URL 的 Host 实现。[上传](../../../backend/worker/pipeline.py#L101) · [S3](../../../backend/app/core/storage.py#L87) · [下载](../../../backend/app/api/works.py#L225)

## 风险说明

成功与文件可用可能分离。对象写入后数据库失败，重试可能重复转码或覆盖。仅有 MinIO 卷无法抵挡宿主失效。

## 改造目标

使用稳定对象键和可验证内容标识，成功只在合法媒体且对象校验通过后落库。可识别缺失、截断和孤儿对象，并能从异地恢复。

## 涉及文件

`backend/app/core/storage.py`、`backend/worker/pipeline.py`、`backend/app/services/handoff_sync.py`、下载路由的必要兼容调整、对账入口和对象备份脚本。

## 修改范围

实现有界上传/读取超时和重试，校验长度与受支持的可信校验和，或回读验证。以暂存、稳定目标键和数据库所有权设计幂等完成。先做只读对账与报警，接入异地备份。验证签名 Host、Range 和对象存储/CDN 直出。

## 明确不修改的内容

不默认清理历史对象，不替换 MinIO 技术栈，不让单条大文件经过 FastAPI。视频媒体规格验证属于 009。

## 数据库影响

优先复用 `video_key` / `file_size`，如需存摘要或存储版本，使用向后兼容字段。旧作品在对账中区分未记录摘要、异常和确认健康。

## 兼容性要求

兼容历史对象键和签名下载响应。跨 S3 实现验证校验和支持，ETag 不普遍等同 MD5。对象备份与数据库备份覆盖相同恢复点要求。

## 测试要求

在隔离真实 MinIO 注入上传失败、中断和数据库落库失败。校验错误长度、对象缺失、恢复已上传对象、Range、备份异地还原与对账。

## 验收标准

- [ ] 上传失败、内容不符或对象缺失时无法写成功。
- [ ] 上传成功但 DB 失败后可恢复并复用已验证对象。
- [ ] 对账能报告缺失和孤儿，恢复演练证明可重新下载。

## 回滚方案

回退读写逻辑时保留新对象、校验元数据和备份。暂停清理，清点未完成对象再切换。回退到未校验流程前禁止继续将未经验证对象标为成功。
