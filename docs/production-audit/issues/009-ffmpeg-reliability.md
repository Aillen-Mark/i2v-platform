# 009 FFmpeg 转码失败处理与媒体验真

**优先级** P0
**审查结论** 已确认，本地 FFmpeg 输入样本复测。已有超时、线程限制和输出大小检查。
**发布状态** 待批准

## 问题背景

成片需满足产品指定的时长、编码、画幅和音频规则。上游资源可能静音、截断或不完整。

## 实际代码依据

`prepare_video()` 固定映射 `0:a:0`，结束后只查输出大小。传入目标 15 秒时，1 秒带音轨样本仍通过；同样时长的静音样本因缺音轨返回 `MEDIA_FAILED`。复测使用真实 FFmpeg 和本地生成样本，上游 HTTP 由测试传输层提供。[现有实现](../../../backend/worker/media.py#L83)

## 风险说明

短片可被传入成功流程，静音成片则失败。临时目录只在正常回收时能自动清理，硬杀或磁盘耗尽会影响后续任务。

## 改造目标

转码结果能够被机器验收。无音轨输入按确认规则补静音 AAC 或允许无音轨，坏片和意外中止进入可恢复或明确失败。

## 涉及文件

`backend/worker/media.py`、`backend/worker/config.py`、媒体测试、生产镜像和临时空间配置。

## 修改范围

使用 FFprobe 校验解码可靠性所需的媒体信息、时长容差、编码、分辨率、音轨和大小。定义下载、探测、转码超时分类，限制临时空间和并发，正常清理加启动巡检。明确子进程退出与硬杀的清理。

## 明确不修改的内容

不调整题目、生成时长要求和前端。不实现对已有历史成片的重新转码；对象发布与对账属于 008。

## 数据库影响

无计划中的结构变化。返回经过探测的媒体信息供 008 使用；不伪造实际时长。

## 兼容性要求

保留 MP4 与 H.264 输出。音轨和时长容差由产品确认，兼顾现有可播放成片，依赖通过同一生产镜像提供 FFmpeg 和 FFprobe。

## 测试要求

真实 FFmpeg/FFprobe 的有声、无声、短片、坏片、超限、转码被终止和磁盘剩余不足测试；HTTP 故障夹具验证下载中断。

## 验收标准

- [ ] 合法无音轨输入按规则交付。短片、坏片、超规格不会交给成功回调。
- [ ] 超时或进程退出后能收敛，临时目录无持续泄漏。
- [ ] 008 可以消费实际媒体校验结果。

## 回滚方案

暂停转码消费并保留上游任务 IDs，切换到上一版媒体处理时继续应用经批准的成片校验门槛。用已持久阶段接续未完成任务。

## 依赖的其他 Issue

无。配合 [006](006-worker-resource-isolation.md) 确定共享资源和镜像，供 [008](008-minio-consistency.md) 调用。
